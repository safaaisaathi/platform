# Driver App PRD

**This is a pointer.** The authoritative copy lives in the driver app's own repo.

👉 **https://github.com/safaaisaathi/driverapp/blob/main/docs/PRD-2-driver-app.md**

**Do not edit this file.** Edit the canonical copy, then bump the `pin` and the `sourceHash` here.

## The contract surface

| Collection | Read | Write | The scope |
|---|---|---|---|
| `drivers` | ✅ own | ❌ | **Field-restricted.** The `driverId` claim. The raw phone is not here |
| `vans` | ✅ own | ✅ telemetry | The `vanId` claim. Only `lastLocation`, `batteryPct`, `status`, `currentTripId` |
| `trips` | ✅ own | ✅ | The `vanId` claim, and the `currentTripId` claim for the D4 scope |
| `trips/{id}/trail` | ✅ own | ✅ | Direct write. The one deliberate exception |
| `wards` | ✅ | ❌ | All of them. The live route screen |
| `routes` | ✅ | ❌ | All of them. The `wardIds` order is load-bearing |
| `complaints` | ✅ trip scope | ✅ 2 fields | Only the complaints whose `wardId` is in the current trip's `wardIds` |
| `notices` | ✅ | ❌ | The van's notices, plus `targetType: all` |
| `notices/{id}/receipts` | ✅ own | ✅ | The read-state |

## The calls it makes

| When | What |
|---|---|
| Sign in | `bindDeviceToVan({ driverCode, installId })` → a custom token with `vanId` and `driverId` |
| Start the shift | `startShift({ driverId, date })` → a fresh token with `currentTripId` |
| End the shift | `endShift({ tripId })` |
| Mark a ward done | `markWardDone({ tripId, wardId, flagged })` |

## The critical warning about this PRD

**Section 0.16 wins over the older sections.**

| Struck lines | What they wrongly say |
|---|---|
| `:61`, `:126`, `:161`, `:217`, `:224`, `:242`, `:267` | That `verifyDriverPin` is the live auth path, that there is a 4-digit PIN, that there is a van picker, that the app signs in with the returned token, and that the backend deploys `verifyDriverPin` and seeds `vanSecrets` |

**All of that is gone.** The PIN flow was deleted. See `../06-changes/CHG-0006-delete-the-pin-flow.md`.

**And one line is wrong for a different reason.** Line `:193` says *"the rules carry no custom-claim checks"*. That contradicts `:68`, which says the rules must check the `vanId` claim. **`:68`'s model wins, and `:193` gets corrected.** See `../06-changes/CHG-0003-scope-the-rules-by-custom-claims.md`.

## The three conflict reasons, and who owns the words

| The server sends | The app shows |
|---|---|
| `vanHeldByAnotherDriver` | `identityShiftConflictOtherDriver` |
| `vanAlreadyClaimed` | `identityShiftConflictClaimed` |
| `staleMarker` | `identityShiftConflictStaleMarker` |

**The app owns the arb strings.** The server never sends English.
